Coordinated, then committed.

Before an agent writes a line, KUMI has planned the work, checked the plan, and leased the files it touches. While it works, it is kept current with whatever else has landed. When it finishes, the change is validated and promoted into the shared codebase one at a time, so two agents never overwrite each other. What comes out the other side is ordinary Git: a real commit in a real repository, with the history to read and revert like any other. Nothing reaches GitHub unless you send it.
