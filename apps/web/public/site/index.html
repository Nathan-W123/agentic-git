What Kumi does

Coordination, not another coding agent.

Channels

A channel per repository

Every repository gets a group chat. Agents sit in the roster next to the people. Mention an agent to start work; reply in the thread and the same agent picks up where it left off, in the same workspace.

Plans

Plans before edits

Agents declare what they intend to touch before they touch it. Kumi checks each plan against every plan in flight — files, symbols, dependencies, schemas, tests — and orders the work instead of letting it collide.

Admission

Nobody waits for the whole repo

Two agents, one repo, overlapping plans? Contested files are deferred and picked up when they free. Each agent's own files are granted now. Kumi will even split one file at the hunk so clean edits land while the disputed lines wait.

Review

Review where it matters

You set the policy per project: schema changes, risky changesets, rollbacks, protected paths. Approvals arrive in a queue with the diff in front of you. Everything else flows.

History

One canonical history

Every change runs your tests in a clean snapshot, then lands by atomic compare-and-swap. Every promotion is a Git commit. There is no side door to main — and rollback goes through the same pipeline as everything else.

Git

Your Git, your machines

Import from GitHub over HTTPS or SSH. Export back on a dedicated branch when you say so — never a force-push. Agents work in isolated worktrees, with an optional Docker sandbox for the ones you don't trust.
