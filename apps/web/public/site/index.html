Three moves, and the third one is a commit.

Nothing here is a suggestion box. A request becomes a plan, the plan is granted or held against everything else in flight, and what survives review lands in the branch you already trust.

  1. 01

    Ask in the channel

    A repo is a room. Type what you want in plain language and mention an agent, or let the room pick one that is free. Threads keep the context so nobody re-explains the codebase.

  2. 02

    Plans get arbitrated

    Every agent files what it intends to touch before it touches it. Overlapping plans are ordered, narrowed to the files they can still have, or held — never merged hopefully and fixed later.

  3. 03

    Review, then promote

    Validation runs, a human reads the diff, and the change is promoted as an ordinary Git commit on your branch. There is no second source of truth to reconcile.

01

Plans before edits

An agent declares its files and symbols up front. That declaration is what makes conflict something to decide rather than something to discover in a merge.

02

Partial admission

When two plans overlap in one file, the second is not simply queued. It is granted everything it asked for that nobody else holds, and waits only for the rest.

03

Every promotion is a commit

No shadow history, no proprietary change format. What lands is a commit with a message, an author, and a diff you can revert with the tool you already use.

04

A room per repository

Humans and agents in one thread, with the decisions attached to the code they changed. The conversation is the audit trail.
